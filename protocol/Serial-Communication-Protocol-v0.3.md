## 1. 串口配置

| 项目 | 取值 |
| ---- | ------ |
| 波特率 | 115200 |
| 数据位 | 8 |
| 停止位 | 1 |
| 校验位 | 无 |
| 硬件流控 | 无 |

注释：

1. 115200 bit/s：每字节在线上占 10 bit（1 起始位 + 8 数据位 + 1 停止位），约 11520 字节/秒。本协议周期消息满载约 1380 B/s（4.1：24B×30Hz=720；4.7：15B×30Hz=450；4.9：21B×10Hz=210），占链路约 12%，余量充足。
2. 数据位 8、停止位 1、无校验：UART 层的标准 8N1 配置。
3. 无硬件流控：不接 RTS/CTS。接收方靠环形缓冲 + CRC 校验处理，不依赖流控。
4. 校验放在帧层做（CRC8 校帧头、CRC16 校整帧），比 UART 的奇偶校验强得多。

## 2. 帧格式

帧结构：`frame_header（5 字节）+ cmd_id（2 字节）+ data（n 字节）+ crc16（2 字节）`，整帧共 **9 + n** 字节。

注释：

1. `frame_header`（5 字节）：帧起始（SOF）、数据长度、包序号、帧头校验。
2. `cmd_id`（2 字节）：消息类型，接收方据此决定如何解析 data。
3. `data`（n 字节）：消息内容，长度由 `data_length` 给出，**上限 64**。
4. `crc16`（2 字节）：对 `SOF` 起、至 `data` 末尾的整帧校验。
   > 注意：末 2 字节是 **CRC16 字段，不是「帧尾定界符」**。

### 2.1 帧头（5 字节）

| 域 | 偏移 | 大小 | 说明 |
| --- | --- | --- | --- |
| SOF | 0 | 1 | 固定 `0xA5` |
| data_length | 1 | 2 | data 的字节数，**≤ 64**，小端 |
| seq | 3 | 1 | 包序号，每发一包自增 1 |
| CRC8 | 4 | 1 | 帧头前 4 字节的 CRC8 |

注释：

1. **SOF = 0xA5**：接收方在「等帧头」状态下找 0xA5；进入帧内后不再把它当帧头。丢同步时扫到下一个 0xA5 即重新同步。
2. **data_length 上限 64（v0.2 新增）**：2 字节字段本身能表示 0–65535，但实际最大 data 只有 15 字节（当前最长消息）。**接收方必须校验：`data_length > 64` → 整帧丢弃，回到「等 SOF」**。接收缓冲固定 `9 + 64 = 73` 字节，永不越界。若不设上限，串口上一个伪 `0xA5` 会被后面的随机字节解释成超长长度，导致解析器长时间空等或缓冲区溢出。
3. **seq**：1 字节计数（0–255，255 后回绕到 0）。两侧各自独立计数，互不相关。用途：丢包检测、ACK 关联、一次性指令去重。不用于重排（单串口链路按序到达）。
4. **CRC8**：只校帧头前 4 字节，用于尽早丢弃坏帧头。
5. **小端（Little-Endian）**：所有多字节字段（`data_length`、`cmd_id`、`crc16`、`float32`、`int16`）均为低字节在前。例：`12 → 0C 00`；`300 → 2C 01`。

### 2.2 CRC

CRC 用于给一段数据算「指纹」：发送方附在帧上，接收方重算，不一致即丢帧。

- **CRC8**：校帧头前 4 字节（`SOF + data_length + seq`），256 种取值，随机损坏漏检率 1/256。
- **CRC16**：校 `SOF` 起至 `data` 末尾，65536 种取值，随机损坏漏检率 1/65536。

**参数**：

| 算法    | 生成多项式                   | 初值     | 输入反射 | 输出反射 | 结果异或   | 测试向量（`"123456789"`） |
| ----- | ----------------------- | ------ | ---- | ---- | ------ | ------------------- |
| CRC8  | 0x31（**反射形式 0x8C**）     | 0xFF   | 是    | 是    | 0x00   | **0x0B**            |
| CRC16 | 0x1021（**反射形式 0x8408**） | 0xFFFF | 是    | 是    | 0x0000 | **0x6F91**          |

> **「反射」这两个字必须写清的理由**：v0.1.1 只写了 `G(x)=x^8+x^5+x^4+1`，这是高位优先（MSB-first）的习惯写法；而裁判系统与本协议算例用的都是**反射实现**（LSB-first 移位方向相反、多项式用反射值 0x8C / 0x8408）。照字面写「从左往右除」，算出的 CRC 与算例永远对不上，联调时会误判成「帧结构错了」。
>
> 另给空数据基线：CRC8(空) = 0xFF，CRC16(空) = 0xFFFF。
> 两份实现必须能对上上面四个向量（`"123456789"` 两条 + 空数据两条），对上了再谈联调。

**字节序**：CRC16 小端存放（低字节在前）。例：CRC16 = 0xB827 → 线上 `27 B8`。

**关于浮点与整数**：

| 方案 | 每轴 | 三轴 payload | 整帧（9+n） | 30 Hz 流量 |
|---|---|---|---|---|
| `float32` | 4 B | 12 B | 21 B | 630 B/s |
| `int16`（0.1 mm/s、1 mrad/s） | 2 B | 6 B | 15 B | 450 B/s |

- 缩放整数（如「×100 存为整数」）就是 **2 字节**，倍率只是小数点约定，**不额外占字节**；比 `float32` 少一半。
- 浮点同样需要在两端做「位模式 ↔ 物理量」的转换，不存在「不用转换」。
- 速度指令（4.1）用 `float32`（目标值，精度优先）；速度反馈（4.7）自 v0.3 起改用 `int16`（与 4.9 一致，0.1 mm/s / 1 mrad/s，精度与 C610 反馈对齐）。视觉侧对比时把 int16 转回 float：vx/vy ×0.0001（→ m/s）、ω ×0.001（→ rad/s）。

## 3. 消息总表

| cmd_id | 方向 | 数据长度 | 功能 | 发送频率 |
| ------ | ------- | ---- | ----- | ------------ |
| 0x0001 | 视觉 → 控制 | 15 | 速度指令 | 30 Hz（名义） |
| 0x0002 | 视觉 → 控制 | 1 | 动作指令 | 事件触发 |
| 0x0003 | 视觉 → 控制 | 3 | ACK | 收到后回 |
| 0x0011 | 控制 → 视觉 | 1 | 模式切换 | 事件触发 |
| 0x0012 | 控制 → 视觉 | 3 | ACK | 收到后回 |
| 0x0013 | 控制 → 视觉 | 1 | 急停/故障 | 事件触发 |
| 0x0014 | 控制 → 视觉 | 1 | 事件上报 | 事件触发 |
| 0x0015 | 控制 → 视觉 | 6 | 速度反馈 | 30 Hz（名义） |
| 0x0016 | 控制 → 视觉 | 12 | 状态帧 | 10 Hz |

注：`cmd_id` 按方向分段——视觉→控制用 `0x0001` 起，控制→视觉用 `0x0011` 起。**每方向可用 `0x0001–0x000F` / `0x0011–0x001F`，各 15 种**（`0x0000` 不用）。

扩充规则：

- 新增消息 = 分配新 `cmd_id` + 加一节（payload 表 + 语义 + 算例）+ 两边实现。帧格式不动。
- 在已有消息里加字段 = payload 变长（`data_length` 随之变大），两边同时改、同时重刷。
- 收到未知 `cmd_id`：**按 `data_length` 跳过 data 段，继续解析下一帧**（不能直接停，否则一帧未知命令会让解析器永久错位）。

## 4. 各消息详细定义

每条消息：`cmd_id`、方向、频率、payload 表（偏移相对 data 开头）、语义、算例。

算例计算步骤：① 按表取一组值；② 小端打包；③ `data_length` = data 字节数；④ 算 CRC8（帧头前 4 字节，初值 0xFF）；⑤ 算 CRC16（SOF 起至 data 末尾，初值 0xFFFF，小端存放）；⑥ 组装。

### 4.1 速度指令（视觉 → 控制）

- `cmd_id`：0x0001
- 频率：30 Hz（名义，跟相机帧率）
- 语义：控制侧把 vx、vy、ω 作为车体目标速度/角速度，执行内环速度闭环。

| 偏移  | 大小  | 字段    | 说明                                   |
| --- | --- | ----- | ------------------------------------ |
| 0   | 4   | vx    | float32，m/s，车体系 x（前）                 |
| 4   | 4   | vy    | float32，m/s，车体系 y（左）                 |
| 8   | 4   | ω     | float32，rad/s，绕 z 轴，**逆时针为正**（自上往下看） |
| 12  | 1   | flags | 目标状态 + 使能 + 急停 + 机构许可，位定义见下          |
| 13  | 2   | ts_ms | uint16，视觉侧处理该帧时的本地毫秒计数（回绕 65.536 s）  |

`flags` 位定义（1 字节）：

| 位      | 含义                                        |
| ------ | ----------------------------------------- |
| bit0~1 | 目标状态：`00`=无目标、`01`=跟踪有效、`10`=目标丢失、`11`=保留 |
| bit2   | 允许运动：1=允许，0=禁止                            |
| bit3   | 请求急停：1=急停（**优先级最高**）                      |
| bit4   | 允许机构动作：1=允许，0=禁止                          |
| bit5~7 | 保留，置 0                                    |

**判读优先级：`bit3` > `bit2` > `bit0~1`。** `bit3=1` 时控制侧立即停车，不看速度值；`bit3=0` 且 `bit2=0` 时保持零速；`bit2=1` 时才执行 vx/vy/ω。目标状态只写日志与状态帧，不参与动作决策。

注释：

1. **flags（v0.2 新增，目标状态并入低 2 位）**：用 1 个字节同时表达「目标状态 / 是否允许运动 / 急停请求 / 机构许可」。这样控制侧能区分「视觉活着但要求零速」与「视觉异常」，视觉侧也能主动请求急停；相比把 `status` 单独占一字节，payload 少 1 字节。
2. **目标状态（bit0~1，原独立 `status` 字节）**：写入控制侧日志与状态帧（4.9 的 fault 之外），便于复盘「车为什么停」。它**不参与动作决策**，动作只看 bit2 与三个速度值。
3. **ts_ms**：uint16、毫秒、回绕。**当前仅用于日志排序与丢帧定位，不用于延迟补偿**——两端毫秒计数未同步，直接相减得到的「延迟」无意义。要做延迟补偿，需先在状态帧里回显接收时刻（见第 6 节）。
4. 频率 30 Hz：MARK 最快约 0.5 m/s，30 Hz 下每周期移动约 1.7 cm，足够精细；低于 20 Hz 会明显抖动。链路占用：24 字节/帧约 2.1 ms，占 33.3 ms 周期的 6.3%。
5. **控制内环是 1 kHz**（`chassis::update()` 每 1 ms 一次，速度环 PID 每周期更新；CAN 发送周期 1 ms）。
6. 坐标系为车体系（x=前、y=左、z=上）。相机系 → 车体系的换算由视觉侧完成，控制侧直接执行。

**算例**：vx=0.5、vy=0、ω=0.3、flags=0x15（`0001 0101`：bit0~1=`01` 跟踪有效、bit2=1 允许运动、bit3=0、bit4=1 允许机构）、ts_ms=1234、seq=0。

- data（15 B）：`00 00 00 3F  00 00 00 00  9A 99 99 3E  15  D2 04`
- data_length = 15（0x000F）→ 线上 `0F 00`
- CRC8 = 0x9C；CRC16 = 0xE403（线上 `03 E4`）
- 完整帧（24 B）：`A5 0F 00 00 9C 01 00 00 00 00 3F 00 00 00 00 9A 99 99 3E 15 D2 04 03 E4`

### 4.2 动作指令（视觉 → 控制）

- `cmd_id`：0x0002
- 频率：事件触发
- 语义：控制侧执行对应动作（一次性指令，必须**幂等**：使同一动作重复执行无副作用）。

| 偏移 | 大小 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 1 | action | 1=开始兑换、2=停止、3=回中、4=退出自动 |

**算例**：action=1、seq=0 → data `01`；CRC8=0x68；CRC16=0xD127（`27 D1`）；整帧（10 B）`A5 01 00 00 68 02 00 01 27 D1`。

### 4.3 模式切换（控制 → 视觉）

- `cmd_id`：0x0011
- 频率：事件触发
- 语义：视觉侧切换模式。

| 偏移 | 大小 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 1 | mode | 0=手动、1=进入自动（RFID 触发）、2=比赛结束 |

**算例**：mode=1、seq=0 → CRC8=0x68；CRC16=0xBBD6（`D6 BB`）；整帧 `A5 01 00 00 68 11 00 01 D6 BB`。

### 4.4 ACK（控制 → 视觉）

- `cmd_id`：0x0012
- 频率：收到需确认的消息后回
- 语义：告诉视觉侧「这条我收到了」，并指明确认的是哪条消息。

| 偏移 | 大小 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 2 | cmd_id | 被确认消息的 cmd_id（小端） |
| 2 | 1 | ack_seq | 被确认消息的 seq |

**算例**：确认 0x0002（动作指令）、ack_seq=1、seq=0 → data（3 B）：`02 00 01`；CRC8=0x27；CRC16=0x4730（线上 `30 47`）；整帧（12 B）：`A5 03 00 00 27 12 00 02 00 01 30 47`。

> v0.3 修订：ACK 增加 `cmd_id` 字段。v0.2 的 ACK 只有 `ack_seq`，无法唯一标识确认对象（不同 cmd_id 的 seq 可能撞值）；本版用 3 字节 `cmd_id + ack_seq` 彻底消除歧义。

### 4.5 急停/故障（控制 → 视觉）

- `cmd_id`：0x0013
- 频率：事件触发
- 语义：视觉侧收到后立即停止发送速度指令，进入故障处理（排查模式）。

| 偏移  | 大小  | 字段         | 说明  |
| --- | --- | ---------- | --- |
| 0   | 1   | fault_code | 见下表 |

| fault_code | 含义                       |
| ---------- | ------------------------ |
| 0          | 人工急停                     |
| 1          | 链路超时（控制侧 100 ms 未收到速度指令） |
| 2          | 电机离线（C610 无 CAN 反馈）      |
| 3          | CAN 总线关闭（bus-off）        |
| 4          | 机构超时（舵机无响应）              |

> 说明：C 板**没有电池电压采样**，因此不设「低电压」故障码。
> 急停由控制侧**本地立即执行**，不依赖本帧送达；本帧只是告知视觉侧。

**算例**：fault_code=0、seq=0 → CRC8=0x68；CRC16=0x1FE7（`E7 1F`）；整帧 `A5 01 00 00 68 13 00 00 E7 1F`。

### 4.6 事件上报（控制 → 视觉）

- `cmd_id`：0x0014
- 频率：事件触发
- 语义：控制侧把本地事件告诉视觉侧，视觉侧按状态机处理。

| 偏移 | 大小 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 1 | event | 1=已夹住可投放、2=夹取失败 |

**算例**：event=1、seq=0 → CRC8=0x68；CRC16=0x826B（`6B 82`）；整帧 `A5 01 00 00 68 14 00 01 6B 82`。

### 4.7 速度反馈（控制 → 视觉）

- `cmd_id`：0x0015
- 频率：30 Hz（与速度指令同频）
- 语义：控制侧回传编码器实测的车体速度，供外环对比。

| 偏移 | 大小 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 2 | vx | 实测 x 方向速度，int16，0.1 mm/s |
| 2 | 2 | vy | 实测 y 方向速度，int16，0.1 mm/s |
| 4 | 2 | ω | 实测角速度，int16，1 mrad/s，逆时针为正 |

注释：

1. **v0.3 改为 int16**（原 float32，payload 12 → 6 字节）：0.1 mm/s 的刻度与 C610 反馈精度（1 rpm ≈ 0.087 mm/s）对齐，范围 ±3.27 m/s 覆盖全速；与 4.9 状态帧的反馈格式一致。视觉侧对比时转回 float：vx/vy ×0.0001（→ m/s）、ω ×0.001（→ rad/s）。
2. 型号：实车为 **M2006（减速比 36:1）**，编码器在电机尾部，由 **C610 电调**经 CAN 反馈给控制板。
3. 该帧非外环必需（位置误差 + 速度前馈即可跑），属于精度增强项。

**算例**：vx=0.5 m/s（=5000）、vy=0、ω=0.3 rad/s（=300 mrad/s）、seq=0 → data（6 B）：`88 13 00 00 2C 01`；CRC8=0x12；CRC16=0xE9D9（线上 `D9 E9`）；整帧（15 B）：`A5 06 00 00 12 15 00 88 13 00 00 2C 01 D9 E9`。

### 4.8 ACK（视觉 → 控制）

- `cmd_id`：0x0003
- 频率：收到需确认的消息后回
- 语义：告诉控制侧「这条我收到了」，并指明确认的是哪条消息。是 4.4 的镜像。

| 偏移 | 大小 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 2 | cmd_id | 被确认消息的 cmd_id（小端） |
| 2 | 1 | ack_seq | 被确认消息的 seq |

**算例**：确认 0x0011（模式切换）、ack_seq=1、seq=0 → data（3 B）：`11 00 01`；CRC8=0x27；CRC16=0x92C5（线上 `C5 92`）；整帧（12 B）：`A5 03 00 00 27 03 00 11 00 01 C5 92`。

### 4.9 状态帧（控制 → 视觉）

- `cmd_id`：0x0016
- 频率：10 Hz
- 语义：控制侧把自身状态一次性告诉视觉侧，让视觉侧知道「控制侧现在能干什么、四个轮子是否在线、有没有故障」。

| 偏移  | 大小  | 字段          | 说明                            |
| --- | --- | ----------- | ----------------------------- |
| 0   | 1   | mode        | 0=手动、1=自动、2=比赛结束              |
| 1   | 1   | wheel_mask  | bit0–3 对应 左前/右前/左后/右后，1=该电机在线 |
| 2   | 1   | fault_code  | 同 4.5 表                       |
| 3   | 1   | link_pct    | 最近 1 s 的速度指令接收率（0–100）        |
| 4   | 2   | vx_fb       | int16，0.1 mm/s                |
| 6   | 2   | vy_fb       | int16，0.1 mm/s                |
| 8   | 2   | wz_fb       | int16，1 mrad/s                |
| 10  | 1   | last_rx_seq | 最近一次被接受的速度指令 seq              |
| 11  | 1   | reserve     | 保留，置 0                        |

> 反馈统一用 int16：0.1 mm/s 的刻度与 C610 的反馈精度（1 rpm ≈ 0.087 mm/s）天然对齐，2 字节够用且范围 ±3.27 m/s 覆盖全速。4.7 自 v0.3 起与本帧一致改用 int16；4.1 速度指令仍用 float32（目标值，精度优先），视觉侧对比时把 int16 反馈转回 float 即可。

**算例**：mode=1、wheel_mask=0x0F、fault=0、link=100、vx=5000(0.5 m/s)、vy=0、wz=300(0.3 rad/s)、last_rx_seq=3、reserve=0、seq=0。

- data（12 B）：`01 0F 00 64  88 13  00 00  2C 01  03  00`
- CRC8 = 0x78；CRC16 = 0x95C0（线上 `C0 95`）
- 完整帧（21 B）：`A5 0C 00 00 78 16 00 01 0F 00 64 88 13 00 00 2C 01 03 00 C0 95`

## 5. 规则

**坏帧**：CRC 校验失败 → 丢弃整帧，不执行；解析器回到「等 SOF」。

**长度越界**：`data_length > 64` → 丢弃整帧，回到「等 SOF」。

**未知 cmd_id**：按 `data_length` 跳过 data 段，CRC16 校验通过后继续解析下一帧；该帧不执行任何动作。

**视觉丢失**：由视觉侧判断；丢失时视觉侧把 `flags` 的 bit0~1 置为 `10`（目标丢失）并清 bit2（禁止运动），控制侧据此保持零速。控制侧不主动判断视觉是否丢失（解耦：视觉决定速度，控制执行速度）。

**链路超时（控制侧安全兜底）**：控制侧超过 **100 ms** 未收到任何速度指令帧 → 速度清零、进入 relax、记日志。这条是本地保护，不发协议消息（链路已断，发了也收不到）；链路恢复即恢复。

> 约束：视觉侧发送频率**不得低于 20 Hz**。若降到 10 Hz（100 ms 正好），超时判定会在边界抖动，车会一顿一顿。

**ACK 范围**：需要 ACK 的——视觉→控制的 4.2 动作指令（由 4.4 确认）；控制→视觉的 4.3 模式切换、4.5 急停/故障、4.6 事件上报（由 4.8 确认）。不需要 ACK 的——4.1 速度指令、4.7 速度反馈（周期数据，下一帧覆盖）、4.9 状态帧、两条 ACK 本身。

**ACK 超时与重发**：发送方发完一次性指令等 ACK，**50 ms** 未收到则重发，最多 3 次；3 次仍无 ACK 记日志并按失败处理。

**重发时的 seq（v0.2 新增）**：一次性指令重发时 **seq 保持与首帧相同**，不递增。

**去重（v0.2 新增）**：接收方对每个 `cmd_id` 记录 `last_exec_seq`；收到 `seq == last_exec_seq` 的帧时 **不重复执行，但照常回 ACK**（否则发送方会一直重发）。这样即使 3 次重发全部到达，动作也只执行一次。

**seq 回绕**：255 → 0。按 `(uint8_t)(now - last)` 计算差值判定丢包；不要写成有符号差值。

**版本**：无 version 字节。改协议时两边同时重刷、改完联调。

**坐标系与单位**：m/s、rad/s；车体系（x=前、y=左、z=上），ω **逆时针为正**。

## 6. 待确认（3 项）

1. **是否做延迟补偿**：若要做，需在 4.9 中增加 `rx_seq(1)` 与 `rx_ms(2)`，视觉侧用回显计算 RTT。**本版暂定不做**——基本循环不需要（MARK 最快 0.5 m/s，延迟 20 ms 只差 1 cm，30 Hz 视觉反馈自己纠过来）；等真机实测、若发现延迟导致抖动或超调，再加。
2. **视觉丢失后是否搜索**：视觉丢失后是停下等（默认，bit2=0）还是主动搜索？若搜索，flags 用 bit0~1=`10` + bit2=1 组合表示“丢了但在找”，还是把保留值 `11` 定义为“搜索中”？搜索 pattern（原地旋转或其他）应由视觉状态机内部定。
3. 内部具体类型/模式枚举字段仍需再考虑完善（可以等）

实现参考（Python，可直接搬成 C）：

```python
def crc8(d, c=0xFF):
    for b in d:
        c ^= b
        for _ in range(8):
            c = (c >> 1) ^ 0x8C if c & 1 else c >> 1
    return c & 0xFF

def crc16(d, c=0xFFFF):
    for b in d:
        c ^= b
        for _ in range(8):
            c = (c >> 1) ^ 0x8408 if c & 1 else c >> 1
    return c & 0xFFFF
```

生产代码可直接用仓库 `libs/crc/include/crc.hpp`（`get_crc8_checksum` / `get_crc16_checksum`），参数与上表一致。
