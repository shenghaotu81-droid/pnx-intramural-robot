# v1.3.0 板端验收与分支闭环

**采集应用以 v1.3.0 收尾。** 本次用默认单缓冲手持拍摄房间，62.203944 秒采到 1,563 帧，实测 **25.11 fps**。首帧时间异常在这次录像中消失，最长采集间隔缩短到 51.490 ms，所有相邻 VPSS 帧号连续。30 fps 仍是配置目标。匀速 MARK 的 q 标定留到后续任务。 [v1.3.0 统计输出](../../evidence/capture_cpp/v1.3.0/profile.txt) · [v1.2.0 同口径输出](../../evidence/capture_cpp/v1.2.0/profile.txt)

## 两次录像的采集节奏

实际帧率按 `(帧数 − 1) / 首尾采集跨度` 计算，P95 使用最近秩。两段均为单缓冲，场景和曝光未作配对控制，写盘停顿的长度也不同。

| 指标 | v1.2.0 | v1.3.0 |
| --- | ---: | ---: |
| 解码帧数／采集跨度 | 1,294／51.650681 s | 1,563／62.203944 s |
| 实际帧率 | 25.03 fps | 25.11 fps |
| 软件帧间隔中位数／P95 | 38.582／47.475 ms | 38.505／47.672 ms |
| 最长软件间隔 | 81.127 ms（952 → 953） | 51.490 ms（46 → 47） |
| 超过 50 ms／超过 60 ms 的间隔 | 10／1（共 1,293 个） | 10／0（共 1,562 个） |
| VPSS 取帧中位数／超时次数 | 37.269 ms／0 | 37.285 ms／0 |
| VPSS TimeRef 增量不等于 1 | 2 次 | 0 次 |
| 压缩队列峰值／上限 | 8／8 | 4／16 |

平均帧率相近，P95 比上次高 0.197 ms。改善集中在启动和最长间隔。新录像全段的 `vpss_pts` 增加 62,204,683 个刻度，按本板样本的微秒尺度换算，与软件跨度只差 0.739 ms。ISP 启动快照为 30.000 fps、曝光 10.177 ms。单帧曝光快照无法确定整段稳态交付约 25 fps 的原因。 [标定 CSV](../../evidence/capture_cpp/v1.3.0/video_19700101_041219_772598_629.csv) · [分段计时 TSV](../../evidence/capture_cpp/v1.3.0/video_19700101_041219_772598_629.timing.tsv)

## 首帧时间

v1.2.0 初始化录像用了 156.855 ms，首帧取帧只花 0.029 ms。第 0 → 1 帧的软件间隔为 28.390 ms，驱动间隔为 152.992 ms，相差 **124.602 ms**，TimeRef 从 228 跳到 232。

v1.3.0 初始化耗时 156.907 ms，日志首行记录主动归还了 1 个启动候选帧。第 0 帧取帧花了 36.597 ms，返回时建立 `t_us=0`。第 1 帧在 38.060 ms 返回，驱动间隔为 37.895 ms，两者相差 **0.165 ms**，TimeRef 从 409 到 410。这个差值衡量两套时钟记录的**首个相邻帧间隔**。从按下录像键到首帧曝光的绝对延迟没有独立测量。 [启动处理及旧版记录](final-round.md) · [新版原始计时](../../evidence/capture_cpp/v1.3.0/video_19700101_041219_772598_629.timing.tsv)

## 最长间隔与写盘

- **第 46 → 47 帧是最长采集间隔。** 获取第 46 帧后，0.492 ms 即进入下一次取帧，随后在 VPSS 调用内等了 50.997 ms。驱动间隔为 48.225 ms，TimeRef 从 455 到 456，两次入队深度均为 1。全段 TimeRef 从 409 连续递增到 1971。
- **第 1358 帧是最长写盘。** 写视频用了 189.880 ms，其间又采到第 1359–1363 帧，队列峰值为 4/16。全程入队等待最长 0.112 ms，送编码前等待上一包最长 0.094 ms。v1.2.0 曾出现 431.853 ms 的写入、队列满和 49.330 ms 的提交等待。本次写入峰值较短，数据确认此次波动被吸收，更大队列对上次同等强度停顿的独立收益仍未量出。
- **稳态交付仍由取帧等待主导。** v1.3.0 的 VPSS 取帧中位数为 37.285 ms，采集线程持帧中位数为 0.460 ms，编码提交中位数为 0.400 ms。398 次 UI 重绘的单次中位数为 14.138 ms，上次 332 次重绘为 21.917 ms。现有板测没有暴露需要继续修改的应用侧瓶颈。 [两版原始日志与复算入口](../../evidence/capture_cpp/README.md)

## 文件验收

FFmpeg 完整解码了原始 H.265 和配套的 `test4.mp4`。两者均为 1,563 帧，可见 1440×1080、编码宽 1472，整段解码像素 SHA-256 相同。原始视频的 1,563 个逐帧像素哈希各不相同。CSV 的三列为 `frame_index,t_us,vpss_pts`，帧号 0–1562 连续，软件时间逐行与 TSV 一致。MP4 按标称 30 fps 封装，播放器显示约 52.10 秒。测量采集间隔应使用 CSV 中的 62.203944 秒时间轴。 [媒体核验表](../../evidence/capture_cpp/media-decode.tsv) · [逐帧像素哈希](../../evidence/capture_cpp/v1.3.0/analysis/decoded.framehash)

同批 JPG 可完整解码到 1440×1080。录像内的 `photo_us` 全部为零，因此本次可核验的是独立照片与视频。抽帧包含首尾、最长间隔两侧和最长写盘所在帧，房间画面与手持运动可辨。 [六帧抽样](../../evidence/capture_cpp/v1.3.0/analysis/sample-frames.jpg) · [原始照片](../../evidence/capture_cpp/v1.3.0/photo_19700101_041219_564540_629.jpg)
