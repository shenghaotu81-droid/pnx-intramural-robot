# Adapter 单元测试报告

独立 Release 构建通过。CTest 注册的 `adapter_test` 通过 1/1 项，测试程序的 10 组共 35 个用例全部通过，其中指令要求的 18 个，补充用例 17 个。验证环境为 GNU C++ 13.3.0、CMake 3.28.3 和 OpenCV 4.6.0。

## 坐标系与配置

相机系采用 OpenCV 约定，`+x` 向右、`+y` 向下、`+z` 向前。车体系以车体中心（轮距中心）为原点，`+x` 向前、`+y` 向左、`+z` 向上。MARK 模型原点在板的左上角，`+x` 沿上边向右，`+y` 沿左边向下，`+z = +x × +y` 朝板背。

测试显式使用默认安装朝向对应的旋转矩阵，把相机 `+x` 映射到车体 `−y`，相机 `+y` 映射到车体 `−z`，相机 `+z` 映射到车体 `+x`。位置取 `R * p_camera + t` 的前两个分量，速度取 `R * v_camera` 的前两个分量。

```text
    [  0   0   1 ]
R = [ -1   0   0 ]
    [  0  -1   0 ]
```

| 配置 | 值 |
| --- | --- |
| `translation`，基础配置 | `(0, 0, 0)` m |
| `translation`，位置偏移用例与速度组 | `(0.1, 0.05, 0.2)` m |
| `follow_target_position` | `(0.5, 0)` m |
| `approach_target_position` | `(0.3, 0)` m |
| `backup_target_position` | `(0.8, 0)` m |
| `follow_target_heading` | `0.1` rad |
| `backup_target_heading` | `-0.1` rad |
| `align_target_heading` | `0.2` rad |
| `scan_angular_velocity` | `0.5` rad/s |

## 补充用例与结果

### 带俯仰的相机外参

将相机光轴向下倾斜 30°，验证配置中的 `rotation` 被用于实际变换。默认 R 会把相机 `+y` 完全映射到车体竖直轴，带俯仰后该轴也会产生车体前后分量。混合分量用例同时核对平移留在车体系，以及外参俯仰下从 `rvec` 提取的 yaw。

```text
           [  0  -1/2  √3/2 ]
R_pitch =  [ -1   0     0   ]
           [  0  -√3/2 -1/2 ]
```

取车体平面分量时，`x = -(camera_y / 2) + (√3 / 2) * camera_z`，`y = -camera_x`。位置在旋转后加 `t` 的平面分量，速度直接使用这两个分量。

| 输入 | 期望 `target_position` | 期望 `target_velocity` | 期望 `target_heading` | 结果 |
| --- | --- | --- | --- | --- |
| 位置、速度均为 `(0, 1, 0)`，零平移，无 `rvec` | `(-0.5, 0)` m | `(-0.5, 0)` m/s | `nullopt` | 通过 |
| 位置 `(0.4, 0.6, 2.0)`，速度 `(-0.2, 0.8, -0.4)`，`t = (0.1, 0.05, 0.2)` m，`rvec = (0, 0.35, 0)` | `(1.5320508075688772, -0.35)` m | `(-0.7464101615137755, 0.2)` m/s | `0.35` rad | 通过 |

### yaw 接近 ±π

以 `δ = 1e-6` rad 从两侧逼近 `atan2` 的分支切点，验证正负方向和跨界后的回绕。四个用例都避开端点本身，以便检查两侧确定的符号。

| `rvec` | 期望 `target_heading`（rad） | 结果 |
| --- | --- | --- |
| `(0, π − δ, 0)` | `π − δ` | 通过 |
| `(0, −π + δ, 0)` | `−π + δ` | 通过 |
| `(0, π + δ, 0)` | `−π + δ` | 通过 |
| `(0, −π − δ, 0)` | `π − δ` | 通过 |

### 三项观测同时出现和缺失

同一个 `Adapter` 先接收齐全的 MARK 观测，再逐项缺失，最后全部缺失。这样能检查各字段独立处理、缺失帧清空相应输出、车速与表观速度各自保留，以及 FOLLOW 期望值在有无观测时均按配置输出。

齐全输入使用默认 R 和零平移，相机位置为 `(0.4, -0.2, 1.2)` m，相机速度为 `(-0.2, 0.25, 0.6)` m/s。`rvec = (a, a, 0)`，其中 `a = π / (2√2)`，表示绕相机 `x`、`y` 方向等分的轴旋转 90°。由该旋转的 `R_cam(0, 0) = 1/2`、`R_cam(0, 2) = 1/√2` 可得 `yaw = atan(√2) ≈ 0.9553166181245093` rad，也能检出把 `rvec.y` 直接当 yaw 的实现。

| 输入变化 | 期望 `target_position` | 期望 `target_velocity` | 期望 `target_heading` | 结果 |
| --- | --- | --- | --- | --- |
| 三项齐全 | `(1.2, -0.4)` m | `(0.6, 0.2)` m/s | `0.9553166181245093` rad | 通过 |
| 只缺位置 | `nullopt` | `(0.6, 0.2)` m/s | `0.9553166181245093` rad | 通过 |
| 只缺速度 | `(1.2, -0.4)` m | `nullopt` | `0.9553166181245093` rad | 通过 |
| 只缺 `rvec` | `(1.2, -0.4)` m | `(0.6, 0.2)` m/s | `nullopt` | 通过 |
| 三项全缺 | `nullopt` | `nullopt` | `nullopt` | 通过 |

三项齐全时另核对车体速度 `(0.3, -0.1)` m/s、车体角速度 `0.2` rad/s 透传。三项齐全和全缺两帧均核对 FOLLOW 的期望位置 `(0.65, -0.12)` m、期望朝向 `-0.3` rad 和空期望角速度，位置和朝向由本组的 `follow_target_position`、`follow_target_heading` 提供。

### SEARCH、ALIGN、BACKUP 与目标独立

每个模式分别输入 MARK 和 TAG，其余输入相同。给这三种模式换一套不同于基础组的配置，以检出目标分支误用、默认值写死、侧向分量丢失或扫描符号错误。

| 模式 | 期望位置 | 期望朝向 | 期望角速度 | MARK 结果 | TAG 结果 |
| --- | --- | --- | --- | --- | --- |
| SEARCH | `nullopt` | `nullopt` | `-0.7` rad/s | 通过 | 通过 |
| ALIGN | `nullopt` | `-0.35` rad | `nullopt` | 通过 | 通过 |
| BACKUP | `(0.65, -0.15)` m | `0.45` rad | `nullopt` | 通过 | 通过 |

## 观察

- 相机下方的单位向量在车体系只产生 `z` 分量，因此平面位置为 `(0, 0)`。相机光心偏移改变了前向位置用例的两个平面分量，速度组仍与纯旋转结果一致。
- yaw 用例验证了绕相机竖直轴 `y` 的两个方向，以及纯俯仰、纯横滚时的零输出。测试保留指令给定的弧度输入，角度说明为近似值。
- 模式组按实际 `DesiredState` 核对了全部三个字段，补充检查 FOLLOW、ALIGN、BACKUP 的角速度为空。基础用例和补充用例的首次完整验证均通过。
- 另用同样的 Release 检查在临时测试副本中将前向位置期望从 `(1, 0)` 改为 `(1.25, 0)`。程序报告用例、字段及两值，继续运行其余九组并返回 `1`。

运行命令和诊断输出说明见[测试说明](../tests/README.md)。
